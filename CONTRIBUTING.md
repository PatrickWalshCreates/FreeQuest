# Contributing to FreeQuest

Thanks for your interest! FreeQuest is young (0.x), so things still move quickly. Bug reports,
ideas, fixes, docs and original art are all welcome.

## The clean-room rule

FreeQuest is an independent implementation. **Do not contribute anything copied or derived from RPG
Maker**: code, plugins, assets, UI layouts or data files. Don't paste them into issues, PRs or AI
prompts either. Recreating general _behavior_ from your own understanding is fine. If you are unsure
whether something is OK, open an issue and ask first.

All art, music and sound in this repo must be original and MIT-compatible. The placeholder art and
audio are generated by scripts in `scripts/`, so they can be regenerated byte for byte.

## Getting started

You need Node.js 22+ and pnpm (the version is pinned in `package.json`). The desktop apps also need
Rust (stable) and, on macOS, Xcode's command line tools.

```sh
pnpm install
pnpm dev      # play the demo at http://localhost:5173
pnpm editor   # the editor in your browser at http://localhost:5174
pnpm check    # lint + typecheck + tests: run before every commit
```

To build the desktop apps yourself:

```sh
pnpm build:mac-player    # the game player for this system (exports are made from it)
pnpm build:editor-app    # macOS: FreeQuest Editor.app and a .dmg in apps/editor/dist-app/macos/
pnpm editor:desktop      # the desktop editor in development mode
```

On a Mac, install Rust with rustup and add both targets
(`rustup target add aarch64-apple-darwin x86_64-apple-darwin`) for apps that run on Apple
Silicon and Intel. The release workflow (`.github/workflows/release.yml`) builds every system's
downloads.

[docs/getting-started.md](docs/getting-started.md) shows the editor from a user's side, and
[CLAUDE.md](CLAUDE.md) holds the architecture notes: how the packages fit together, the file
format rules, and why things are the way they are. Read the parts near what you're changing.

## Ground rules

- `packages/core` is pure logic: no PixiJS, no DOM, no Node APIs. Lint and the compiler enforce this.
- The runtime only draws core's state; screens keep their logic in PixiJS-free controllers with
  tests. The editor works the same way: logic in `packages/editor-core`, React only draws it.
- Project files are written only through `stableStringify` from `@freequest/schema`.
- Changing a file format means bumping its `formatVersion` and adding a migration, an old-format
  fixture and a test. Projects made with any earlier version must keep opening.
- New behaviour needs tests. If you change the demo's events, keep `demo-quest.test.ts` passing.
- Keep dependencies few. A new one needs a good reason, a compatible licence, and
  `pnpm gen:notices` re-run so the licence notices stay complete.

## Making a change

1. Open an issue first for anything bigger than a small fix, so we can agree on the approach.
2. Keep pull requests focused: one change, with tests, and docs updated where they describe it.
3. `pnpm check` must pass. CI runs it and the build on every pull request.
4. Describe what changed and how you checked it (for UI changes, a screenshot helps).

## Releases

FreeQuest has one version, in the root `package.json`. `pnpm version:set <version>` writes it
everywhere else, and each release gets an entry in [CHANGELOG.md](CHANGELOG.md).
